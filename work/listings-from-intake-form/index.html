Case study · Real estate · Listing automation

One intake form, three published listings.

A corporate housing company sends every new property owner the same questionnaire. We built browser agents that turn the answers into finished listings on Vrbo, Zillow Rental Manager and TurboTenant, and stop for a person before anything goes live.

The problem

The same facts, typed three times.

The client rents furnished homes, condos and a studio. Each one goes on Vrbo as a nightly stay, and on Zillow and TurboTenant as a furnished month-to-month rental for traveling nurses, military families, contractors and people relocating for work.

That means three wizards per property, each with 20 to 40 screens asking for the same rent, deposit, fees, rules, amenities and photos in a different order. Every site also has its own traps. Vrbo’s wizard won’t take the real minimum stay, so it has to be fixed after publishing. Zillow quietly switches a month-to-month lease to one year. TurboTenant wants a single unit filed as a condo, never an apartment.

Done by hand, details drift between sites. When we audited the portfolio’s live listings, we found one-bedroom units described as having two bedrooms, one home listed as sleeping 8, 10 and 14 on different sites, and deposits that didn’t match.

What we built

One agent per platform, one form for all three.

Each agent is a written playbook that drives a real browser session. It was built from screen recordings of the work being done by hand, with every field label checked against the real screens.

How a listing run works

The agent fills the screens. A person approves the listing.

  1. 01

    Read the form once

    The agent reads the owner’s questionnaire, maps each answer to the platform’s fields and fills the rest from the company’s house defaults, like the listing contact and renters insurance.

  2. 02

    Ask about the gaps

    It never guesses the facts that matter: address, bedrooms and bathrooms, rent, deposit, pets and parking. If the form is silent on one, it asks. Owners often leave parking blank, and a garage in a photo doesn’t mean a guest can park in it.

    Human step
  3. 03

    Write the title and description

    It writes copy in the company’s style for each audience, a vacation stay on Vrbo and a flexible furnished rental on the other two, and checks nearby landmarks with a web search instead of making them up.

  4. 04

    Fill every screen

    It works through the wizard, uploads photos in room-by-room order, and reads each value back from the page after setting it. One dropdown looked set but quietly reverted, so now every field gets checked.

  5. 05

    Stop before Publish

    Publishing is the one step that can’t be undone, so the agent stops there. Its summary sorts every field into three groups: from the form, a house default, or flagged for the owner.

    Human step
  6. 06

    Fix what the wizard got wrong

    After publishing, it goes back for the settings the wizard can’t take or gets wrong: the real minimum stay and booking type on Vrbo, and the lease length on Zillow.

How we estimated. Both figures are estimates, not log measurements. The by-hand times come from the screen recordings used to build the agents and the number of screens on each platform. In one recording, TurboTenant’s screens from leasing basics to photos took about 8½ minutes for someone with every answer ready, before writing a description or uploading a photo. The 30 minutes counts only what needs a person: answering the agent’s questions (5–10 minutes), reading three pre-publish summaries (10–15) and signing in or verifying a phone number when a site asks (5–10). The agents’ own run time isn’t counted, because nobody has to watch it. Across nine properties, that’s roughly 27 hours by hand against about 4½, around 6× less.

Guardrails

Nothing goes live without a yes.

  • One approval, in the right place

    The agent runs the whole wizard on its own and stops once, right before Publish, with a summary of where every value came from.

  • A short list it never guesses

    Address, bed and bath count, rent, deposit, pets and parking always come from the owner. Everything else falls back to a house default and is reported as one.

  • Trust the screen, not the playbook

    These sites change their layouts often. When a screen doesn’t match the playbook, the agent stops and asks instead of clicking where a button used to be.

  • A person handles identity

    The agent never gets past a login page or a bot check on its own, and never tries a password. Those go to a person.

  • Gaps go back into the form

    Every question the agents had to ask got added to the owner’s questionnaire. It now covers what all three platforms need, so owners answer once and listings go out without a round of follow-up emails.
